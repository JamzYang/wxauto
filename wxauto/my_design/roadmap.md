# 微信RPA（WeChat, Windows）— 分阶段开发路线图（Python 版 MVP）

参考文档：
- 架构：`apps/wechat-rpa/docs/architecture.md`
- 详细设计：`apps/wechat-rpa/docs/detailed-design.md`

---

## 总体假设与范围
- 仅支持 Windows 微信客户端；以 UIAutomation 为主，OCR 兜底。
- 本地 Agent 负责“群消息采集 + 自动发言（含 @）”；云端负责决策/RAG/编排。
- 强化人机并发保护、速率与静默、审计/黑匣子、紧急停用。
- 技术栈与目录结构按文档推进（`uiautomation`、`rapidocr-onnxruntime`、`httpx`、`tenacity`、`loguru`、`sqlite3` 等）。

---

## M1（PoC，~1周）：基础可达性与链路打通
- 核心价值交付目标
  - 让 Agent 基于 UIAutomation 在目标微信上“看得见、读得到、发得出”，并打通云端“注册/心跳/消息上报/回复下发”的最小闭环。
  - 白名单会话的未读消息读取与本地去重生效，能发送简单文本（含有限 @）。

- 验收标准
  - 冒烟用例通过（≤10s，见 `detailed-design.md` 第18章）：可定位“会话列表、消息区、输入框、发送按钮、@ 候选浮层”；失败自动切只读并写入审计。
  - 云端接口最小闭环（见 `architecture.md` 第7章、`detailed-design.md` 第12/15章）：
    - 成功调用：`/api/v1/agents/register`、`/api/v1/agents/heartbeat`、`/api/v1/messages/ingest`、`/api/v1/messages/replies`。
    - 请求含并透传 `trace_id`，心跳与上报具备 `tenacity` 指数退避重试。
  - 读取“未读区间最近 N 条”（默认 N=20，可配），`Deduper/Idempotency` 生效（文本/语音转写/元信息）。
  - 基础发言与有限 @：在白名单群内发送文本，@ 白名单成员（稳定性 M2 强化）。
  - 托盘最小可见性：切换“只读/读写/暂停/紧急停用”，状态展示正确。

- 关键任务与产出物
  - UIA 适配器最小实现：未读检测、进入会话、消息区读取、输入框写入与发送、@ 候选选择。
  - 云端客户端：Pydantic DTO + `httpx` 客户端 + `tenacity` 重试 + 本地幂等策略。
  - 本地存储：初始化 SQLite（`conversations`、`messages_idempotency`）。
  - 日志与审计最小化：`loguru` 滚动；审计表写入；结构化包含 `trace_id`。
  - 目录结构搭建与冒烟用例脚本。

---

## M2（MVP，~1周）：稳定发言、OCR 兜底与护栏完善
- 核心价值交付目标
  - 在多样窗口状态下稳定完成“读取→上报→下发→@→发送”的全链路，失败有清晰回退与审计。
  - 提供 OCR 小范围兜底、活动感知只读切换、速率/静默策略、人机并发保护、黑匣子与全链路 trace。

- 验收标准
  - 稳定 @：三段式回退（UIA 候选→纯文本@→无@降级）；白名单与别名映射严格校验（`detailed-design.md` 第6、10章）。
  - OCR 兜底：UIA 失败触发局部截图 + `rapidocr`；受频控（单会话/全局最小间隔、每分钟上限）、尺寸限制与置信度阈值治理（第8章）。
  - 活动感知：检测前台/输入活跃/焦点变更；命中则本轮只读，下一轮指数退避（第9章）。
  - 策略与限流：白名单群与 @ 白名单强校验；每群最小间隔、全局上限；夜间静默（第10章）。
  - 审计/黑匣子/追踪：
    - 审计记录“前100字摘要、@目标、结果、trace_id”等；黑匣子包含控件快照、局部截图（频控）、错误栈、操作序列，本地加密（第16章）。
    - 统一 `trace_id` 贯穿并与云端对齐（`architecture.md` 第7章）。
  - 错误与降级：滑动窗口阈值触发自动只读，托盘提示（第11章）。
  - 指标观测：打点核心指标（`uia.locate.success_rate`、`ocr.trigger.rate`、`reply.send.success_rate` 等，见第17章）。

- 关键任务与产出物
  - OCR 兜底流水线与 `configs/` 参数化（见第14章）。
  - 活动感知器与只读切换逻辑，前台占用预算 ≤500ms。
  - 策略/限流与夜间静默配置（第10、14章）。
  - 审计/黑匣子实现与脱敏最小化策略（第16、22章）。
  - 全链路 trace 对齐与日志结构化字段。

## M3（稳态增强，持续迭代）：鲁棒性与可运营化
- 核心价值交付目标
  - 选择器鲁棒性提升、配置中心/AB 灰度、可选服务化与自动更新；运维可见性与回归测试体系完善。

- 验收标准
  - 选择器库：多候选 + 权重/阈值 + 灰度 A/B，在不同客户端版本保持高命中（`detailed-design.md` 第4章）。
  - 配置中心化：选择器、策略、OCR、限流等支持版本化与热更新（最小可行：本地配置 + 云端拉取/回滚）。
  - 测试与回归：
    - 单元：选择器打分、幂等键、退避/限流策略（第19章）。
    - 集成：UIA/OCR/云端联调；回归：选择器库升级的 A/B 对比。
  - 可选服务化与更新：Windows Service 运行与自动更新通道（`detailed-design.md` 第20章）。
  - 指标与告警：完善 `ops/` 面板与报警规则（结合仓库 `ops/grafana/`、`ops/alerts/`）。

- 关键任务与产出物
  - 选择器命中统计与失败样本库（`selectors_stats` 表，见第13章），驱动灰度与权重调参。
  - 配置拉取与本地持久化、版本回滚机制。
  - 服务化脚本、自动更新策略说明与风控（签名/白名单）。
  - 监控与报警阈值治理，Runbook 完善（`detailed-design.md` 第21章）。

---

## 横向里程碑与保障（贯穿）
- 非功能与护栏：人机并发、速率/静默、安全合规、紧急停用、日志最小化与脱敏（`architecture.md` 第8/9章；`detailed-design.md` 第10/16/22章）。
- 数据与模型一致性：Pydantic 模型与 SQLite 结构同步更新（`detailed-design.md` 第12/13章）。
- 打包与分发：PyInstaller 单文件，`assets/` 与 `configs/` 归档（第20章）。
- 风险管理：UIA 控件变更、OCR 波动、@ 误命中、前台打扰等均有回退与治理（第23章）。

---

## 交付节奏与检查点
- 每日：提交可运行增量 + 冒烟用例通过（≤10s）。
- 每阶段结束：演示“端到端闭环”场景，导出审计与黑匣子样例；提交阶段报告（覆盖指标、失败样本与问题单）。
