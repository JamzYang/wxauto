# 微信RPA（Windows）- 需求文档（MVP）

## 1. 背景与目标
- 仅针对 Windows 桌面端微信/企业微信（根据部署选择其一或兼容）。
- 在 Windows 上提供“微信群消息的自动读取与自动回复”能力，作为本地消息通道适配器，弥补企业微信机器人无法服务外部群的限制；业务自动化执行由独立 executor 负责。

## 2. 范围（MVP）
- 消息采集（只读）：
  - 仅处理“带未读红点”的白名单会话；进入会话后，仅读取未读区间内的最近 N 条消息，识别发送者、时间、消息文本；富文本/图片读取失败时触发局部截图 + OCR 兜底。
  - 去重（原则）：读取后先在本地排重，仅对“未上报过”的消息进行上报；云端将相同内容视为同一事件，避免重复触发。
- 自动发言（含 @）：
  - UIA 聚焦输入框 -> 写入文本（ValuePattern 或粘贴）-> 回车/点击发送。
  - 支持 @ 指定人：通过“@姓名”触发候选浮层并精确匹配；失败时回退纯文本但需二次确认（可配置）。
- 云端对接：
  - 上报“消息入口”API，云端进行 GPT 决策/RAG，返回“回复内容”或下发任务。
  - 接收云端“回复下发”API 指令并在指定会话中发言。
- 本地执行器联动：
  - 收到云端任务（如开票/查报表）后，本地执行器执行并回报结果；必要时触发群内状态/结果通知。
  - 任务由 Cloud Brain 编排并下发至独立 executor；`wechat-rpa` 仅负责群消息的上报与回告，不直接调度 executor。

## 3. 非功能性要求
- 可观测性：全链路 trace_id；关键操作（读取/发言/失败）打点；与云端日志对齐。
- 稳定性：
  - 轮询节流（3–5s）；白名单会话限制；窗口抢焦最小化。
  - 多策略定位（ControlType+Name+层级）；坐标点击仅作最后兜底。
  - 按“未读标记（红点/数字/加粗）”进行定向轮询与跳转，避免全量遍历会话列表。
- 性能：
  - UIA 为主，OCR 少量触发；截图区域与频率可配；CPU 负载受控。
 - 安全与合规：
   - 少抢焦、少模拟输入：优先使用 UIA 的 Value/Invoke 等 Pattern 直接赋值/调用；仅在必要时短暂激活窗口并立即还原；避免高频 SendKeys 与坐标点击。
   - 白名单访问：仅处理白名单群与成员（@对象），禁止访问非授权会话；支持配置化。
   - 传输与鉴权：HTTPS + Token/mTLS；与云端链路追踪对齐；失败自动降级为只读模式。
   - 最小化与脱敏：日志与审计仅记录必要摘要（如前100字）；黑匣子加密、受控上传；不上传业务产出文件。
 - 可见性/操作者提示：
   - 自动化操作期间提供显著指示（托盘图标高亮/角标、悬浮小条“正在自动回复…/正在执行…”，或任务弹窗），并在完成后清除。
   - 支持“一键暂停/中断”入口（托盘菜单/快捷键），中断后立即切只读并记录审计。

## 3.1 人机并发防漏（原则）
- 只读未读：仅处理带未读标记的白名单会话；若真人先行点开清零，不立即清除我们的未读偏移，待读取成功后再推进。
- 冗余读取：进入会话读取未读区间内最近 N 条，配合去重实现“至少一次读取”。
- 先排重后上报：本地先排重，仅对“未上报”的消息上报；云端将相同内容视为同一事件，重试不产生副作用。
- 定时退避：UIA/OCR 暂失败不清未读，记录黑匣子并退避重试（2s→4s→8s），避免与真人操作争抢。
- 最小打扰：减少前台抢焦；探测用户活跃输入时延后我们的操作。
- 跳过争抢：检测到窗口/焦点频繁变更时，本轮只读不发言，下一轮再补读。
- 可视提示与人工中断：自动化期间有明显指示器，人工可随时暂停/中断，避免误操作造成遗漏。
- 审计与回溯：黑匣子记录失败上下文，支持后续复盘与补偿策略。
 - 时间戳增量回退：每会话维护 `last_processed_ts`；当未读红点识别失败或异常升高时，采用“时间窗口 W + 冗余 N 条”的增量扫描，从 `last_processed_ts - W` 开始读取并在本地合并去重后仅上报新消息，成功后推进 `last_processed_ts`。
 - MVP 并发简化：
   - 用户活跃输入即切换只读；
   - 当前聚焦会话不自动发言；
   - 每轮仅处理少量会话（可配置上限）；
   - 速率限制 + 指数退避；
   - 风险动作（发言、@）优先在“非前台”或用户空闲时执行。

## 4. 关键能力说明（Hybrid）
- UIAutomation 主通道：
  - 定位会话列表、未读标记、消息区、输入框（Edit/RichEdit）、发送按钮（Button）。
  - 读取文本消息；获取发送者、时间等可读属性。
  - 未读标记识别：检测会话列表项上的“红点/未读数字/字体加粗”等属性（如 `Name/Text/IsOffscreen/SelectionItem` 组合）；优先使用多特征选择器并支持配置化匹配。
- OCR 兜底：
  - 当 UIA 获取失败时，对消息气泡区域做局部截图并使用中文OCR模型识别；标注低置信度。
- 发言与 @：
  - 通过 UIA 往输入框注入文本；插入“@姓名”并选择候选。
  - @ 三段式回退：
    1) UIA 候选选择（精确匹配，优先白名单成员）；
    2) 失败回退“纯文本 @姓名”（可配置发前确认/提示）；
    3) 仍高风险时“无 @ 发送 + 明确提示人工处理”，并在审计中标注降级原因。
  - 可选能力：发前预览开关（可按策略对特定模板、含@消息强制预览）；@ 白名单强校验（避免 @ 错人，非白名单阻断或需二次确认）。

- 语音消息（原则）：
  - 识别“这是语音消息”及其元信息（发送者、时间、时长、未读状态等），不依赖坐标。
  - 默认启用“微信内置转文字”：检测到新语音后，通过 UIA 调用气泡菜单“转文字”，获取转写文本，并在上报时携带 transcript 字段。
  - 失败与回退：若转写失败或无法读取文本，记录黑匣子并退避重试；多次失败则仅上报“语音类型事件（无转写）”。严格控制前台占用时长与打扰。
  - 范围与速率：仅对白名单会话启用；遵循速率限制、用户活跃感知与可视指示，可随时暂停/只读。

## 5. 安全护栏
- 意图白名单（一期可执行范围）：仅允许自动发“澄清、进度、结果、致谢/告知”等标准模板；涉及金额/承诺/敏感内容须发前确认或人工发送。
- 速率限制：每群最小间隔；全局速率上限；夜间静默时段。
- 去重与防循环：基于上行消息hash去重；检测“机器人↔机器人”自激活并短时静默。
- 紧急停用：托盘菜单/快捷键立即停发；云端策略下发失败时默认“只读”。
 - 边界：紧急停用仅影响群消息发送能力（自动切换为只读），不影响 executor 的运行与控制，executor 由云端统一管理。
 - 少抢焦/少模拟输入：尽量后台读取；必要前台操作在 200–500ms 内完成并还原；优先 ValuePattern/InvokePattern，粘贴与坐标点击仅兜底。
 - 用户活动感知：检测用户活跃输入时延后我们的操作，避免打断真人。
 - 失败降级：UIA 连续失败或异常增多时自动降级为“只读”模式，并记录黑匣子；重试采用退避（2s→4s→8s）。
 - 截图/OCR 频率控制：仅在 UIA 读取失败时对目标控件区域小范围截图；限制频率与分辨率，标记低置信度。
  - 运行指示器与人工中断：自动化执行期间展示明显状态指示；允许操作者随时暂停/中断并切换至只读模式。
  - 并发保护（MVP）：用户活跃输入即只读、当前聚焦会话不自动发言、一轮仅处理少量会话、风险动作尽量在非前台或空闲时执行。

## 6. 与云端接口（草案）
- Agent 注册/心跳（本地→云端）：
  - `POST /api/v1/agents/register`（注册），`POST /api/v1/agents/heartbeat`（心跳） — 草案
  - 字段（建议）：
    - `agent_type`: `wechat-rpa`
    - `capabilities`: `[message_ingest, message_send, mentions, whitelist_control, blackbox_audit]`
    - `channel`: `WeChat` | `WeCom`
    - `account_id`, `client_version`, `display_dpi`
    - `modes`: `read_only` | `read_write`
    - `policy_versions`: 速率/静默/白名单配置版本
    - `trace_id`、`host_meta`（系统信息、网络环境摘要）
- 消息入口（本地→云端）：`POST /api/v1/messages/ingest`
  - 字段：tenant_id, conversation_id, sender_id, sender_display, timestamp, raw_text, attachments[], trace_id, client_meta。
- 回复下发（云端→本地）：`POST /api/v1/messages/replies`
  - 字段：conversation_id, reply_text, mentions[], send_mode(auto|confirm), trace_id, ttl。
- 任务进度通知（本地→云端→可选群发言）：RPA 任务触发状态/结果事件，云端生成回复并下发。

## 7. 本地数据与审计
- 本地状态：每群偏移量、最后处理消息的唯一键、会话缓存等（SQLite/JSON）。
- 审计日志：会话ID/群名、发送内容摘要（前100字）、@目标、时间戳、执行结果、trace_id；脱敏处理。
 - 黑匣子：采集/发言失败时保存控件属性快照、局部截图、错误栈与操作序列；按权限上报云端并可审计下载。
 - 去重思路（非技术）：按会话维护“已处理范围”，先在本地排重再上报；云端把“同一消息”视为同一事件，重试不应产生额外影响，从而实现“至少一次读取 + 不重复触发”。
  - 语音去重原则：以会话、发送者、时间（标准化）、语音时长等元信息组合判断同一性；重试/重复读取在云端被视为同一事件，避免重复触发。
  - 转写幂等键：若内置“转文字”成功，生成 `content_hash = hash(normalize(transcript))` 并与元信息一同作为幂等键；若无转写结果，则退回使用“元信息幂等键”（会话+发送者+时间+时长）。
  - 时间戳增量状态：按会话维护 `last_processed_ts` 与最近一次稳定读取窗口参数；当未读标记策略不可靠时，从 `last_processed_ts - W` 起做“窗口 W + 冗余 N 条”的增量扫描；本地合并去重（幂等键：会话+发送者+标准化时间+内容/转写hash），成功上报后推进 `last_processed_ts`。
  - 选择器库与回退链：以“选择器库抽象（多特征匹配）+优先级/回退链配置”形式记录本地版本号与命中统计，用于后续优化与灰度。

## 7.1 工程化控制（新增）
- 选择器库抽象：以组件化方式管理 `ControlType/Name/AutomationId/层级` 等候选，支持按权重/优先级匹配与灰度；统一回退链配置（UIA→OCR→坐标兜底仅在必要时）。
- 启动后嵌入式冒烟用例：进程启动后 10 秒内执行关键控件可达性检查（会话列表、消息区、输入框、发送按钮、@候选浮层），失败则退为只读并提示人工；冒烟结果写入审计。
- 指示器 + 一键暂停：维持显著状态指示与一键暂停入口，保证人机并发时优先保护用户体验。

## 8. 风险与应对
- UIA 控件变更：采用多特征定位与配置化选择器；快速回归脚本适配。
 - 未读标记样式变更：支持多种候选特征（红点/数字/加粗），通过配置切换与A/B匹配；必要时回退按会话最近更新时间与偏移量判定。
- OCR 不稳定：仅兜底，小范围触发；对结果标记置信度并允许降级处理。
- @ 命中错误：白名单成员精确匹配；可开启发前预览确认。
- 风控与打扰：速率限制、静默时段、白名单会话与人工开关。

## 9. 里程碑（建议）
- M1（PoC，~1周）：UIA 可读范围验证；白名单会话读取与去重；基础发言（不含@/或有限@）。
- M2（MVP，~1周）：稳定@选择；OCR兜底；安全护栏与审计；云端接口联调；黑匣子。
- M3（稳态，~后续）：更强的选择器鲁棒性；配置中心；C# 服务化评估（可选）。

## 10. 验收标准
- 能在白名单群稳定读取与自动发言（含常见@）≥ 98% 成功率（客户端不改版前提）。
- 速率限制与静默策略生效；紧急停用可用。
- 审计与黑匣子可回溯；云端全链路可观测。
 - 自动化操作期间有明显可见的指示器；可通过托盘/快捷键进行暂停或紧急停用。
